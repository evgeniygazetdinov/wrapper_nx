# Решение проблем с отсутствующими символами

## Ошибка: "could not find symbol InitalizeCriticalSection"

### Причина
Символ `InitalizeCriticalSection` (или `InitializeCriticalSection`) ищется библиотекой, но не найден в таблице импортов.

### Решение

1. **Убедитесь, что проект пересобран:**
   ```bash
   make clean
   make
   ```

2. **Проверьте, что символы добавлены в `source/imports.c`:**
   ```c
   { "InitializeCriticalSection", (uintptr_t)&ret0 },
   { "InitalizeCriticalSection", (uintptr_t)&ret0 },  // Typo variant
   ```

3. **Проверьте порядок вызовов в `main.c`:**
   - `so_resolve()` должен вызываться ДО `so_execute_init_array()`
   - Это гарантирует, что импорты разрешены до выполнения инициализации

4. **Если ошибка все еще есть:**
   - Проверьте, что используется правильная версия `libGame.so`
   - Убедитесь, что файл не поврежден
   - Проверьте логи для других ошибок

### Порядок вызовов (важно!)

```c
so_resolve(dynlib_functions, dynlib_numfunctions, 1);  // Разрешить импорты
patch_openal();  // Применить хуки
patch_opengl();
patch_game();
so_execute_init_array();  // Выполнить инициализацию ПОСЛЕ разрешения импортов
```

### Отладка

Если ошибка сохраняется:

1. **Включите DEBUG_LOG:**
   ```c
   // В source/config.h
   #define DEBUG_LOG 1
   ```

2. **Проверьте логи:**
   - Смотрите `debug.log` на Switch
   - Ищите другие ошибки

3. **Проверьте версию библиотеки:**
   - Убедитесь, что используется правильная версия `libGame.so`
   - Проверьте, что файл не поврежден

4. **Проверьте зависимости:**
   - Убедитесь, что все необходимые библиотеки доступны
   - Проверьте, что OpenAL правильно инициализирован
