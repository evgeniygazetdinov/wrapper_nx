# Руководство по адаптации wrapper для Bully Android

## Обзор

Этот wrapper был создан для Max Payne Mobile. Чтобы адаптировать его для Bully, нужно выполнить несколько шагов.

## Шаг 1: Извлечение файлов из APK

1. **Извлеките APK файл Bully** (он должен быть в формате ZIP)
2. **Найдите .so файл** в папке `lib/arm64-v8a/` внутри APK
   - Обычно называется `libBully.so` или похоже
   - Убедитесь, что это **arm64-v8a** версия (не armeabi-v7a)

### ⚠️ ВАЖНО: Если в APK нет папки `lib` и `.so` файлов

Если вы не нашли папку `lib` в APK, возможны следующие варианты:

#### Вариант A: Библиотеки в OBB файле
Некоторые игры (особенно старые версии) хранят `.so` файлы в OBB файле:
1. Найдите OBB файл (обычно `main.*.com.rockstar.bully.obb`)
2. Распакуйте OBB (это тоже ZIP архив)
3. Ищите `.so` файлы внутри OBB, возможно в папке `lib/` или прямо в корне

#### Вариант B: Split APK (разделенные APK)
Современные Android игры могут использовать split APK:
1. Ищите файлы с именами типа:
   - `bully-base.apk`
   - `bully-arm64_v8a.apk` или `bully-*-arm64_v8a.apk`
   - `bully-config.*.apk`
2. `.so` файлы могут быть в `bully-arm64_v8a.apk` или подобном файле
3. Распакуйте все split APK файлы и ищите `.so` в каждом

#### Вариант C: Android App Bundle (AAB)
Если у вас файл `.aab` вместо `.apk`:
1. Переименуйте `.aab` в `.zip` и распакуйте
2. Внутри будет папка `base/` или `split_*`
3. Ищите `.so` файлы в `base/lib/arm64-v8a/` или `split_*/lib/arm64-v8a/`

#### Вариант D: Библиотеки в assets
Редко, но возможно:
1. Проверьте папку `assets/` в APK
2. Ищите `.so` файлы там (возможно с другими именами)

#### Вариант E: Установленная версия на устройстве
Если у вас есть установленная версия Bully на Android устройстве:
1. Используйте `adb pull` для получения APK:
   ```bash
   adb shell pm path com.rockstar.bully
   adb pull /data/app/com.rockstar.bully-*/base.apk
   ```
2. Или используйте приложения типа "APK Extractor" на устройстве
3. Полученный APK должен содержать все библиотеки

#### Вариант F: Проверка структуры APK
Распакуйте APK и проверьте структуру:
```bash
unzip -l bully.apk | grep -i "\.so"
unzip -l bully.apk | grep -i "lib/"
```
Это покажет, есть ли вообще `.so` файлы в APK.

**Или используйте готовый скрипт:**
В проекте есть скрипт `check_apk_structure.sh`, который автоматически проверит структуру APK:
```bash
./check_apk_structure.sh bully.apk
```
Скрипт покажет:
- Все найденные `.so` файлы
- Структуру папок
- Наличие папок `lib/` и `assets/`
- Информацию о пакете
- Рекомендации по дальнейшим действиям

3. **Извлеките содержимое папки `assets`** из APK
4. **Найдите OBB файл** (обычно `main.*.com.rockstar.bully.obb` или похоже)
   - Распакуйте его содержимое
   - **Проверьте OBB на наличие .so файлов!**

## Шаг 2: Определение имени .so файла

После извлечения APK, проверьте какое имя у .so файла. Обычно это:
- `libBully.so`
- `libbully.so`
- `libBullyAndroid.so`
- `libgame.so` (общее имя для некоторых игр)
- `libmain.so` (если используется Unity или другой движок)

**Важно:** Запишите точное имя файла!

### Если .so файл все еще не найден

Если после всех проверок вы не нашли `.so` файл, возможны следующие причины:

1. **Это не Android версия игры**
   - Убедитесь, что у вас именно Android APK, а не iOS или другая версия
   
2. **Игра использует другой движок**
   - Некоторые игры могут использовать Unity, Unreal Engine или другие движки
   - В этом случае структура может отличаться
   - Проверьте, есть ли в APK папка `assets/bin/Data/` (Unity) или другие специфичные папки

3. **Версия APK не содержит нативных библиотек**
   - Очень редко, но возможно, что игра полностью на Java/Kotlin
   - Для Bully это маловероятно, так как это 3D игра

4. **APK поврежден или неполный**
   - Попробуйте скачать APK из другого источника
   - Проверьте целостность файла

**Рекомендация:** Если вы не можете найти `.so` файл, попробуйте:
- Использовать другую версию APK Bully
- Проверить форумы или репозитории, где обсуждают портирование Bully
- Убедиться, что у вас правильная версия игры (некоторые версии могут отличаться)

## Шаг 3: Анализ символов в .so файле

Вам нужно найти следующие символы в .so файле Bully. Используйте инструменты:
- `nm -D libBully.so` (или как там называется ваш .so)
- `objdump -T libBully.so`
- `readelf -Ws libBully.so`

### Критически важные символы для поиска:

1. **Функция инициализации графики:**
   - В Max Payne: `_Z12initGraphicsv`
   - В Bully может быть похоже или отличаться

2. **Функция показа джойстика:**
   - В Max Payne: `_Z12ShowJoystickb`
   - В Bully может отличаться

3. **Главная функция приложения:**
   - В Max Payne: `_Z14NVEventAppMainiPPc`
   - В Bully может быть другой

4. **Глобальные переменные:**
   - `StorageRootBuffer` - путь к данным
   - `IsAndroidPaused` - флаг паузы
   - `UseRGBA8` - формат текстуры

5. **Специфичные для Max Payne символы (могут отсутствовать в Bully):**
   - `_ZN24MaxPayne_ConfiguredInput10sm_controlE` - управление вводом
   - `_ZNK21MaxPayne_InputControl9getButtonEi` - получение кнопки
   - `_ZNK24MaxPayne_ConfiguredInput10readCrouchEv` - чтение приседания

## Шаг 4: Изменения в коде

### 4.1 Изменить имя .so файла

В файле `source/config.h`:
```c
#define SO_NAME "libBully.so"  // замените на реальное имя вашего .so
```

### 4.2 Изменить список проверяемых файлов данных

В файле `source/main.c`, функция `check_data()`:

Замените список файлов Max Payne на файлы Bully. Пример:
```c
static void check_data(void) {
  const char *files[] = {
    // Добавьте здесь файлы, которые нужны Bully
    // Например:
    "data",
    "audio",
    // и другие файлы, которые вы нашли в OBB
    "",
  };
  // ... остальной код
}
```

**Как определить нужные файлы:**
- Запустите игру и посмотрите, какие файлы она пытается открыть
- Проверьте структуру OBB файла
- Посмотрите логи ошибок

### 4.3 Изменить символы в main.c

В файле `source/main.c`, в функции `main()`:

Найдите строки:
```c
strcpy((char *)so_find_addr("StorageRootBuffer"), ".");
*(uint8_t *)so_find_addr("IsAndroidPaused") = 0;
*(uint8_t *)so_find_addr("UseRGBA8") = 1;

uint32_t (* initGraphics)(void) = (void *)so_find_addr_rx("_Z12initGraphicsv");
uint32_t (* ShowJoystick)(int show) = (void *)so_find_addr_rx("_Z12ShowJoystickb");
int (* NVEventAppMain)(int argc, char *argv[]) = (void *)so_find_addr_rx("_Z14NVEventAppMainiPPc");
```

Замените имена символов на те, что вы нашли в .so файле Bully.

**Важно:** Если какой-то символ не найден, игра выдаст ошибку при запуске. Это поможет понять, что нужно изменить.

### 4.4 Адаптировать хуки в game.c

В файле `source/hooks/game.c`:

1. **Удалите или закомментируйте специфичные для Max Payne хуки:**
   - `MaxPayne_ConfiguredInput_readCrouch` и связанные символы
   - `WeaponSwiper::Draw` (меню оружия)

2. **Проверьте все хуки с именами функций:**
   - Все функции с префиксом `_Z` - это C++ mangled имена
   - Они могут отличаться в Bully
   - Если игра выдает ошибку "could not find symbol", значит нужно найти правильное имя

3. **Адаптируйте управление:**
   - Функции `WarGamepad_*` могут работать как есть, если Bully использует ту же систему
   - Или нужно будет найти аналогичные функции в Bully

### 4.5 Изменить путь к OBB файлу

В файле `source/hooks/game.c`:
```c
#define APK_PATH "main.obb"  // замените на имя OBB файла Bully
```

## Шаг 5: Тестирование и отладка

1. **Соберите проект:**
   ```bash
   make clean
   make
   ```

2. **Скопируйте файлы на Switch:**
   - Создайте папку `/switch/bully/` (или как хотите назвать)
   - Скопируйте `project.nro` в эту папку
   - Скопируйте `.so` файл в эту папку
   - Скопируйте все файлы данных из OBB в эту папку
   - Скопируйте содержимое `assets` в эту папку

3. **Запустите и смотрите ошибки:**
   - Если игра не запускается, читайте сообщения об ошибках
   - Ошибка "Could not find symbol" означает, что нужно найти правильное имя символа
   - Ошибка "Could not find [файл]" означает, что нужно добавить файл в список проверки

## Шаг 6: Полезные инструменты для анализа

1. **Для анализа .so файла:**
   - `nm -D libBully.so | grep -i init` - найти функции инициализации
   - `nm -D libBully.so | grep -i graphics` - найти функции графики
   - `strings libBully.so | grep -i storage` - найти строки с путями

2. **Для отладки:**
   - Включите `DEBUG_LOG` в `config.h` (раскомментируйте `#define DEBUG_LOG 1`)
   - Это поможет увидеть, какие функции вызываются

## Возможные проблемы

1. **Игра использует другую систему управления:**
   - Bully может использовать другую систему ввода, не `WarGamepad_*`
   - Нужно найти правильные функции в .so файле

2. **Разные форматы данных:**
   - Bully может использовать другие форматы файлов
   - Проверьте структуру OBB файла

3. **Отсутствующие функции:**
   - Некоторые функции Max Payne могут отсутствовать в Bully
   - Нужно будет закомментировать или адаптировать соответствующие хуки
